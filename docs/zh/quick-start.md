# 快速上手

有人给了你一串分享码。走完这一页，你会有一个属于自己的网站，用自己的域名，地址栏里带小锁。

全程用同一个例子，你可以拿自己的屏幕逐行对：

```
  账号      ana
  容器      wp-1，在机器 hk-1.example.com 上
  域名      example.com 和 www.example.com
  机器地址  203.0.113.7
```

你的每个值都会不一样，除此之外都一样。

```
  1  领取分享码
  2  两个密码
  3  登进去
  4  装个网站
  5  添加你的域名
  6  把域名指到机器上
  7  把每个域名分流到对应的服务
  8  开启 HTTPS
  9  出问题时去哪看日志
```

第 1 到 4 步只要那串码就够了。第 5 步开始需要一个域名 —— 随便哪家买都行，一年也就一杯咖啡钱。

---

## 1. 领取分享码

别人发给你的东西，长这样两种之一：

```
  https://hqno.de/redeem?code=HQ-7F3K-2M9P
  HQ-7F3K-2M9P
```

打开那个链接，或者进面板的 **容器 → 兑换分享码**。没登录的话它会先让你登录或注册，然后自己
回到这串码上。注册只问用户名、邮箱和密码，别的不问 —— 这里只有一种账号，一个账号可以持有
任意多个人给你的容器。

```
  ┌ 兑换分享码 ──────────────────────────────────
  │  分享码          [ HQ-7F3K-2M9P    ]
  │  Shell 用户名    [ ana             ]  可选
  │  Shell 密码      [                 ]  留空则生成
  │                                       [ 领取 ]
  └──────────────────────────────────────────────
```

下面两栏留空就自动帮你生成。**你应该看到：**

```
  ┌ 归你了 ──────────────────────────────────────
  │  怎么登进去                        只显示一次
  │  ssh u7k2m9p@hk-1.example.com
  │  密码   8Kd2-vQx7-mR
  │  离开页面前先把密码复制走 —— 面板不保存它。
  └──────────────────────────────────────────────
```

离开页面之前先把密码存到安全的地方。它只显示这一次，别处都没有；丢了只能重设一个，找不回来
（第 2 步）。

还有两件事现在就该知道：领取会把登录名和密码重写，所以发码给你的人从此进不来了。另外，码在
生成后 **14 天**失效 —— 过期的码不等于容器丢了，跟对方再要一串新的就行。

**如果账号是别人替你开的**，你有用户名但还没有密码。用**忘记密码**填主机方给的那个邮箱，
邮件里的链接会把它变成一个你能登录的账号。

## 2. 两个密码

最容易搞混的一件事。你有两个密码，开的是不同的东西：

```
  面板密码   ──▶  你登录的那个网站
  shell 密码 ──▶  你的那一份容器
```

第一个在 **账号** 页面改：

```
  ┌ 账号 ────────────────────────────────────────
  │  用户名   ana
  │  邮箱     ana@example.com          [ 修改 ]
  │  密码     ••••••••                 [ 修改密码 ]
  └──────────────────────────────────────────────
```

第二个在容器页面的 **操作 → Shell 登录 → 重置密码**：

```
  ┌ 重设 shell 登录 ─────────────────────────────
  │  Shell 用户名  [ u7k2m9p ]
  │  新密码        [          ]
  │                留空则自动生成
  │                                    [ 设置 ]
  └──────────────────────────────────────────────
```

新密码只显示一次，旧的立刻失效 —— 所以别在正忙着别的事的时候做这一步。面板里的用户名永远
不变；上面那个 shell 用户名是另一个名字，想改多少次都行。

想用密钥而不是密码登录？机器的大门可以放公钥，但**面板目前没有填公钥的地方** —— 找主机方
帮你加。

## 3. 登进去

容器页面上写着你要的三样东西 —— **用户**、**主机**，以及主机后面那个端口。拼起来就是命令：

```
  ssh u7k2m9p@hk-1.example.com          端口是 22
  ssh u7k2m9p@hk-1.example.com -p 2222  其它端口
```

然后打开一个终端：

```
  Windows 10 或更新   PowerShell，或者 Terminal
  macOS               终端（Terminal）
  Linux               任意终端
```

```
  $ ssh u7k2m9p@hk-1.example.com
  The authenticity of host 'hk-1.example.com' can't be
  established. Continue connecting? yes
  Password:                    ← 粘贴密码；屏幕上不会有反应
  root@wp-1:~#
```

输入或粘贴密码时屏幕上什么都不显示，这是故意的，不是键盘坏了。那句 authenticity 的问题只在
第一次出现。

**你应该看到**一个以 `#` 结尾的提示符。现在你是自己这套系统的管理员：

```
  root@wp-1:~# free -h        有多少内存
  root@wp-1:~# df -h /        有多少磁盘
  root@wp-1:~# systemctl      有什么在跑
  root@wp-1:~# reboot         重启你这一份，很安全
```

如果进不去，跳到[第 10 步](#_10-出问题的时候)—— 常见原因就是密码不对，或者容器已经停了。

## 4. 装个网站

敲一个词：

```
  root@wp-1:~# app-setup
```

```
  ┌ 套件安装 ─ Web 服务器 ─ 数据库 ─ 开发插件 ─ 系统 ────
  │
  │ ▸ LNMP           网站服务器 + 数据库 + PHP
  │   WordPress      十个网站里四个在用的建站软件
  │   MariaDB        只要数据库
  │   Node.js        ...
  │
  │ 磁盘 600M 内存 768M
  │ ↑↓←→ 移动    回车 打开    ↑ 走到顶是「返回」
  └──────────────────────────────────────────────
```

```
  ↑ ↓ ← →   移动
  回车       打开
  ↑ 走到顶   返回
  L          中文 / English
  q          退出
  鼠标也能用
```

第一次建站，从这两个里挑一个，回车进去，按 `[安装]`：

```
  LNMP        网站服务器、数据库和 PHP，已经接好
  WordPress   上面那一套，再加 WordPress 和它的数据库
```

按之前先看那一行占用 —— 你这一份装不下的时候它会**标红**，这是没人在装了四分钟之后才告诉你
的那个数字：

```
  磁盘 600M  内存 768M      装得下
  磁盘 600M  内存 768M      这一份太小了   ← 红色
```

然后它就开始跑，你看着它跑：

```
  ┌ 正在安装 LNMP ───────────────────────────────
  │  Reading package lists... done
  │  Setting up nginx (1.24.0)
  │  Setting up mariadb-server
  │  Setting up php8.2-fpm
  │  ████████████████████░░░░░  78%
  └──────────────────────────────────────────────
```

**你应该看到**在自己这一份里面，网站服务器已经在回应了：

```
  root@wp-1:~# curl -I http://127.0.0.1
  HTTP/1.1 200 OK
  Server: nginx/1.24.0
```

这就是「网站已经存在」—— 还没牵扯到任何域名和证书。如果这一步不回应，后面域名怎么弄都没用，
所以就在这里解决掉。

它还替你做了两件事：它生成的密码写进 `/root/.app-setup/` 里，不会哗哗滚过屏幕；卸载软件从不
删你的数据 —— 会先把你会心疼的东西挪到 `/root/` 下面，并且告诉你挪到哪了。

不用菜单也能干同样的事，写脚本的时候用得上：

```
  root@wp-1:~# app-setup list
  root@wp-1:~# app-setup install lnmp
  root@wp-1:~# app-setup status nginx
  root@wp-1:~# app-setup docs wordpress
```

想装的东西不在列表里？你可以自己加一条：[添加你自己的软件](/app-setup-sources)（英文）。

## 5. 改配置

回车打开你的软件。按钮都在它那一页上，「东西在哪改」的答案也在：

```
  ┌ Nginx ───────────────────────────────────────
  │ [卸载] [停止] [开机自启] [参数设置]
  │ [使用说明] [日志]
  │
  │ 参数设置
  │   这个软件没有可以改的参数。
  └──────────────────────────────────────────────
```

现在随镜像发布的软件，几乎都是在自己的配置文件里改，而不是在表单里改 —— 而**使用说明**会把
文件路径一个个列出来，你不用自己找：

```
  root@wp-1:~# app-setup docs nginx
  Nginx

    Where things are
      /var/www/html                     你的网站文件
      /etc/nginx/conf.d/app-setup.conf  默认站点
      /var/log/nginx/error.log          出问题先看这个
```

所以改一次配置就是三条命令，中间那条最重要 —— 配置写坏了它会拒绝重载，而不是把你的网站
弄挂：

```
  root@wp-1:~# nano /etc/nginx/conf.d/app-setup.conf
  root@wp-1:~# nginx -t
  nginx: ... test is successful
  root@wp-1:~# systemctl reload nginx
```

**如果某个软件确实有参数**，表单里会是它自己的字段，加三个按钮：

```
  [ 保存并应用 ]   写进去，并且立刻生效
  [ 保存 ]         只写进去 —— 屏幕会说「还没生效」
  [ 取消 ]         这次改动作废
```

```
  root@wp-1:~# app-setup set myapp port=8080   脚本里这么写
```

你自己往菜单里加的东西可以声明这些字段，见
[添加你自己的软件](/app-setup-sources)（英文）。

## 6. 添加你的域名

在容器页面上找到 **Domains** 这张卡片：

```
  ┌ Domains ──────────────────────────────── 0 of 10 ┐
  │  No domains yet.                                 │
  │                                   [ Add domain ] │
  └──────────────────────────────────────────────────┘
```

> 这张卡片目前只有英文界面，所以下面几张图里保留原文。

先加 `example.com`，再加 `www.example.com` —— 每个域名单独一行：

```
  ┌ Domains ──────────────────────────────── 2 of 10 ┐
  │  example.com       DNS ·  HTTP ·  HTTPS ·     ⚙  │
  │  www.example.com   DNS ·  HTTP ·  HTTPS ·     ⚙  │
  │  Point them at 203.0.113.7                       │
  └──────────────────────────────────────────────────┘
```

这一步只是告诉机器：这些域名是你的。它**不会**去动你域名商那边的解析，也**不会**给你证书 ——
那是接下来两步的事。

一般允许 10 个域名，卡片上会数着；具体数字主机方可以改。

---

## 7. 把域名指到机器上

上面那张卡片写着要指向的地址 —— 例子里是 `203.0.113.7`。去卖你域名的那家，找到 DNS 或
「解析记录」，加两条：

```
  类型   主机记录  值             对应的网址
  ────   ────────  ───────────    ─────────────────
  A      @         203.0.113.7    example.com
  A      www       203.0.113.7    www.example.com
```

`@` 就是不带前缀的主域名。如果面板给你的是一串域名而不是四段数字，那就改用 `CNAME`，值填那串
域名。

过几分钟，从你自己的电脑上验一下：

```
  $ nslookup example.com
  Name:     example.com
  Address:  203.0.113.7      ← 就是那台机器，对了
```

同时，卡片上的徽章会自己变绿。不用刷新，也不用按任何东西：

```
  DNS ·  HTTP ·  HTTPS ·   还没检查
  DNS ✓  HTTP ✕  HTTPS ·   域名到位了，但没人回应
  DNS ✓  HTTP ✓  HTTPS ·   有回应了 —— 现在可以要 HTTPS
  DNS ✓  HTTP ✓  HTTPS ✓   齐了
```

新加的域名，机器会每隔几分钟查一次，解析出来之后就查得稀一些。域名设置里的 **Test** 可以立刻
查一次。

**有个坑。** 如果那台机器在家庭或办公室的路由器后面，路由器必须把网页流量转发给它。否则你的
域名解析得好好的，但永远没人回应。这件事只有主机方能弄，找他们。

## 8. 把每个域名分流到对应的服务

这一步能把一份容器变成好几个网站：

```
  example.com       ──▶  80     你刚装的网站服务器
  www.example.com   ──▶  80     同一个
  api.example.com   ──▶  3000   你自己写的程序
```

点某个域名后面的齿轮：

```
  ┌ api.example.com ─────────────────────────────────┐
  │  DNS ✓   HTTP ✓   HTTPS ·                        │
  │  DNS      points here (203.0.113.7)              │
  │  HTTP     port [ 3000 ]             [ Test ]     │
  │  HTTPS    ( ) Your certificate · SNI passthrough │
  │               port [ 443  ]         [ Test ]     │
  │           (•) Managed                            │
  │               port [ 3000 ]                      │
  │                     [ Request certificate ]      │
  │                        [ Save ]  [ Delete ]      │
  └──────────────────────────────────────────────────┘
```

那个端口框填的是**你这一份容器里面的端口**，也就是访问这个域名的人最终到达的地方。普通网站
留着 80；自己写的程序就填 3000。

**Test** 会替你连一下，然后告诉你结果：

```
  ✓  answered in 3 ms              回应了
  ✕  nothing is listening on 3000  你的程序没在听
  ✕  the container is not running   先把容器启动起来
```

保存的时候，如果那个端口还没打开，它会顺手打开，并且明确告诉你：

```
  Publishing container port 3000 restarted this
  container's network for a moment.
```

字面意思：这一份容器的网络断了一瞬间，正在连着的连接会重连一次，同一个端口不会再有第二次。

## 9. 开启 HTTPS

两条路，可以按域名分别选。都在你刚打开的那个设置里。

### 主机方托管的证书 —— 一个按钮

选 **Managed**，按下按钮：

```
  [ Request certificate ]
    HTTPS ⟳  requesting…               一分钟以内
    HTTPS ✓  issued · renews 30 days before it expires
             （到期前 30 天自动续）
```

不用装东西，之后也不用记着 —— 续期它自己做，而且离到期还早就做了。注意端口框会锁到你的 HTTP
端口上：这条路上机器把明文交给你容器里的一个端口，所以只需要填一个端口。

两个前提，缺哪个按钮都会告诉你：

```
  ✕  example.com does not arrive here yet    → 第 7 步
  ✕  nothing answers on port 3000            → 第 8 步
  ✕  five requests this week already — try 18 Aug
     （这个域名本周已经要过五次了，到 18 号再来）
```

最后那条在你连按两次之前就该看一眼：同一个域名**一小时一次、一周五次** —— 这是签发证书那边的
规矩，按第六次会把你自己这个域名锁上好几天。自动续期从不受这个限制，所以它只会在你折腾配置
的时候咬你。

### 自己的证书 —— 私钥在你手上

选 **Your certificate · SNI passthrough**，填上你这一份里面处理加密流量的端口：

```
  访客 ══加密══▶ 机器 ══原样转发══▶ 你的那份，443
```

机器不解开就转发过去，所以你的证书不会出现在容器之外 —— 反过来，容器之外也没有任何东西会替你
续期。在容器里面按常规办法申请一张，自己续着；徽章会告诉你你的容器实际在提供什么：

```
  HTTPS ✓  valid until 4 Nov          有效到 11 月 4 日
  HTTPS ✕  expired 12 days ago        12 天前就过期了
  HTTPS ✕  the certificate is for another name
                                      证书不是这个域名的
```

面板上没有上传证书的地方。这条路上，证书属于解开流量的那一头，也就是你的容器里面。

两条路都一样，**你应该看到：**

```
  浏览器里输入：  example.com   ──▶  🔒  你的网站
  不算验证过：    curl http://example.com
```

在浏览器地址栏里输入不带前缀的域名。浏览器会先试加密的那一边，而那正是你要验的东西；一条不
加密的 curl 什么都证明不了。

## 10. 出问题的时候

四个地方，按这个顺序看：

```
  1  徽章          HTTP ✕ connection refused on 3000
  2  容器里面      systemctl status myapp
  3  安装日志      /var/log/app-setup/wordpress.log
  4  面板          这一份容器自己的历史，最新的在上面
```

徽章会指出坏的是哪一半 —— 域名、端口，还是证书 —— 而且看一眼不花钱。然后进容器里面：

```
  root@wp-1:~# systemctl status myapp
  ● myapp.service — failed (exit code 1)
  root@wp-1:~# journalctl -u myapp -n 20
  root@wp-1:~# journalctl -xe          最近的全部
```

从菜单装的东西都有自己的日志，出错的时候屏幕上会直接把路径打出来：

```
  WordPress failed — exit 1.
  The log is /var/log/app-setup/wordpress.log
```

面板还记着你这一份被做过什么，最新的在最上面：

```
  11 Aug 14:02  certificate issued for example.com
  11 Aug 13:58  api.example.com: http port 80 → 3000
  11 Aug 13:40  example.com added
```

有两种故障哪里都不留话，靠样子认：

```
  服务反复挂掉，日志里什么都没有   ──▶ 内存
  "no space left on device"        ──▶ 磁盘满了
```

| 你看到的 | 通常是什么 |
|---|---|
| 登不进去 | 容器停了、到期了，或者因为流量被暂停了。面板会说是哪一种。 |
| 一直重复问密码 | 密码不对。重设一个（第 2 步）—— 旧的谁也变不出来。 |
| 浏览器找不到这个域名 | 解析问题。按第 7 步在自己电脑上查一下那两条记录。 |
| 域名找到了，但没人回应 | 要么你这一份里那个端口上没程序在听（第 8 步），要么机器所在的路由器没把网页流量转发进来（第 7 步）。 |
| 浏览器显示的是别人的网站 | 域名没指到这台机器，或者你在面板里加了域名但没去改解析。 |
| 证书警告 | 域名和证书对不上，或者证书过期了。托管模式下重新要一次；自己的证书就在容器里面续。 |
| 要证书被拒，还给了个日期 | 这个域名本周的五次用完了，等到那个日期。 |
| 服务挂了但日志里什么都没有 | 内存。让它跑着，同时看容器页面上的内存数字。 |
| no space left on device | 磁盘。你这一份里所有东西共用一个额度。 |
| 面板说机器离线 | 主机方那台机器没在向面板报到。你的容器很可能还好好跑着，只是按钮得等。找主机方。 |
| 什么都很慢 | 你的 CPU 份额，或者那台机器本身很忙。容器页面上的曲线是最近一周的。 |

## 11. 丢不起的东西放哪

重装之后只有一个目录还在。别的都是「系统 + 你对它的改动」，重装换掉的正是这一部分：

```
  /etc/nginx/nginx.conf     没了
  /var/www/site             没了
  /root/notes.txt           没了
  /data/mysql               还在
  /data/uploads             还在
```

所以数据库、上传的文件、任何你会心疼的东西，放到 `/data` 下面，然后让服务指向那里。

还有三件会让网站停下、但什么都不会删的事，各一行：

```
  流量用完       ─▶ 暂停；下个月窗口一到就回来
  到期日过了     ─▶ 停掉；主机方可以续
  你按了重装     ─▶ 全新系统，/data 保留
```

这三件各自的细节 —— 还有碰到限额是什么感觉 —— 写在
[使用你的容器](/using-your-container)（英文）里。
