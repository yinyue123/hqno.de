# 给节点跑性能测试

重装一次，等半小时，你会拿到一个网址：一张说明这台机器到底是什么的页面 ——
CPU、硬盘、内存、IP 的信誉、到十几个地方的速度、回国的九条线路 ——
中文、英文、法文、德文，谁看它就用谁的语言。

它是拿来贴在你卖节点的地方的，或者直接发给问"我买的是啥"的人。

**页面上没有任何一项是被第三方核实过的。** 它写的是机器测出来的东西，加上你自己填的东西。
这句话两个方向都要记住：正因如此它对你的机器是诚实的，
也正因如此别人发给你的页面，值多少完全取决于你信他多少。

## 1. 跑起来

你的容器需要一块 `/data` 盘。这次运行留下的所有东西都在那儿，
包括那把之后能改这张页面的唯一钥匙，而 `/data` 是重装唯一不抹掉的地方。
没有它你只能发布一次，之后永远改不了。容器页面上会写你有没有。

在容器里开一个 shell：

```
reinstall ref ghcr.io/yinyue123/nodequality
```

命令就这一条。重建过程中你的 SSH 会断 —— 这是应该的 ——
大约一分钟后回来，测试已经自己开始跑了。

::: tip 为什么是重装，而不是"装个程序"
镜像本身就是那个程序。检测需要的每一个工具都已经编好放在里面了，
所以整个过程只下载测速用的数据，别的什么都不下 ——
不会有包管理器在磁盘测试跑到一半的时候插进来，把磁盘成绩搅乱。
:::

## 2. 等着，想看就看

**二十到五十分钟**，会走掉**几个 GB**的测速流量，算在你容器的额度里。
小套餐先看一眼额度还剩多少。

```
tail -f /data/nodequality/first-boot.log
```

跑完之后，这个日志的最后一行就是你的网址。任何时候也可以直接问：

```
nq-shop show
```

它会打印出它保存的每一个文件，以及发布之后的地址：

```
published as https://shop.hqno.de/r/xxxxxxxxxx
```

整个测试**只跑一次**。判断依据是有没有已发布的页面，
所以跑到一半挂掉的话，下次容器开机会重来；已经成功的则永远不会重跑 ——
重启容器不会让它再测一遍。

## 3. 改页面

测出来的数是机器的。价格、名字、联系方式、备注是你的，它们都在一个文件里：

```
/data/nodequality/shop.json
```

用什么改都行 —— 容器里的 `vi`，或者走 SFTP —— 然后：

```
nq-shop build      # 把你改的折回页面里
nq-shop publish    # 覆盖掉已发布的那张
```

两条都很快。**都不会重跑测试**，网址也不变 ——
`/data` 里那把钥匙就是"这张页面归你改"的凭据。

::: warning 钥匙就是页面本身
`/data/nodequality/credentials.json` 是唯一能替换你这张页面的东西。
丢了的话，页面会一直挂在那儿、一直能看、永远改不动。
它能扛过重装，因为它在 `/data` 里；扛不过删容器。
页面重要的话，把它备份出来。
:::

### 里面写什么

```json
{
  "shop": {
    "title": { "zh": "洛杉矶 CN2 GIA", "en": "Los Angeles CN2 GIA" },
    "plans": [
      {
        "name": { "zh": "标准 · 1C / 1 GB", "en": "Standard · 1C / 1 GB" },
        "currency": "¥", "monthly": 45, "yearly": 450,
        "rows": [
          { "k": "CPU", "v": "1 vCPU" },
          { "k": "@k_ram", "v": "1 GB" },
          { "k": "@k_traffic", "v": "100 GB" }
        ]
      }
    ],
    "contacts": [ { "k": "@k_tg", "v": "@@yourname" } ]
  }
}
```

价格要写成**数字**，不是字符串。写 `45`，不要写 `"45"` ——
年付省多少是从这两个数算出来的，`450` 对上 12×45，四种语言都会自己印出"省 17%"。

## 4. 四种语言，以及哪些部分跟着读者走

页面能渲染成 **zh · en · fr · de** 四种，由读者挑。
你写的文字分三类，行为各不相同，而这个区别就是整件事的窍门：

| 你文件里写的 | 渲染出来 | 什么时候用 |
|---|---|---|
| `"@k_ram"` | 内存 / Memory / Mémoire / Speicher | 任何有标准叫法的东西 |
| `{"zh": "…", "en": "…"}` | 你自己的措辞，一种语言一份 | 表里不可能知道的东西 |
| `"1 GB"` | 到哪儿都是 `1 GB` | 数字、单位、AS 名 |

所以一行只写一次：

```json
{ "k": "@k_ram", "v": "1 GB" }
```

法国人看到的就是 **Mémoire — 1 GB**，你一个法文字都不用写。

只有你才叫得出名字的部分 —— 机器叫什么、套餐叫什么 —— 用对象那种写法。
不用四种都填；缺的语言会退回英文，再退回中文，再退回有什么用什么：

```json
"title": { "zh": "洛杉矶 CN2 GIA", "en": "Los Angeles CN2 GIA" }
```

两个会咬人的细节：

- `@` 是查表的起手式。Telegram 账号写成 `"@yourname"` 会被当成键去查，
  出来变成 `yourname`，那个符号没了。要写 `"@@yourname"`，两个 `@` 表示一个字面的 `@`。
- 查不到的键会把自己去掉 `@` 印出来，这正好用来抓错字：
  页面上如果写着 `k_rma`，那你本来想写的是 `@k_ram`。

想指定语言就带上查询参数，不带就让浏览器自己决定：

```
https://shop.hqno.de/r/xxxxxxxxxx?lang=en
```

## 5. 只跑其中一部分

每一步都是独立的命令，任何一条都能单独跑。第一次跑完之后，常用的是这几条：

```
nq-shop bench                    # 只跑 CPU 跑分，两分钟左右
nq-shop collect --skip ip,hw,net # 只跑回国的九条线路
nq-shop build                    # 用磁盘上现有的数据重建页面
nq-shop publish                  # 推上去，还是同一个网址
```

`--skip` 接一串逗号分隔的名字，可选 `ip`、`hw`、`net`、`bench`、`route`，
所以 `nq-shop collect --skip net` 就是"除了那几个 GB 之外的全套"。

::: warning `hqnode exec` 六十秒就放弃
如果你是从**宿主机**这边驱动，而不是在容器里开 shell，
`hqnode exec` 会在一分钟后返回 `context deadline exceeded`，还把锅甩给 agent。
命令本身在容器里照样跑，你丢的只是输出。
长命令要么用 detached 方式启动，要么干脆在容器里开个 shell 跑 —— 那边没有这个限制。
:::

## 6. 这张页面不会告诉你的事

- **上面没有一个分数是读者能自己核实的。** CPU 那几块来自 sysbench、7-Zip、
  OpenSSL 和 stress-ng，没有一个会把结果发布到任何公开的地方。
  它们跟另一张同样方式生成的页面比是诚实的，跟别的东西比则毫无意义。
- **多线程那个分数是偏乐观的。** 它取的是 cgroup 上限，
  而在 hqnode 上那是你的突发额度，不是卖给你的核数。
- **自由文本保持采集时的语言。** AS 名、城市名不会翻译；
  固定词表 —— 是/否、通/不通、风险等级 —— 会翻。
- **线路那两节要求路由真的能追踪。** 容器里是能追的，但只能走 UDP；
  你的宿主机如果把 UDP 过滤掉了，这两节会是空的，而不是错的。
