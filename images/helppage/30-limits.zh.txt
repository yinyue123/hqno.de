title: 你的配额
summary: 五个数字，各自撞上去是什么感觉，以及在哪儿看

下面每一个数字，登录时那块屏上都有，`dashboard` 里还能再看一遍：

    dashboard          全部
    dashboard net      只看流量表
    dashboard cpu mem  只看这两项

数字来自两处，都不是估算：卖给你多少来自面板，正在用多少是打印前一刻从这台宿主机
上读出来的。

== CPU：只会变慢，不会被杀 ==

撞上 CPU 上限没有任何报错，就是所有东西都变慢。没有东西要修，也没有信号可捕获 ——
如果一次构建比昨天慢了一倍，通常就是它。

你的核数与其说是上限，不如说是下限。机器上别人不要的核你可以拿去用，所以卖了两核
的容器，在邻居空闲时能跑到两核以上，等他们醒来再回落到两核。这也是同一个跑分测两
次得到两个结果的原因：诚实的那个读数，是机器忙的时候测的那个。

如果主机方卖给你的是「批处理」容器，规则不同但更简单：所有人吃完剩下的才是你的，
而你跑的任何东西都不会拖慢别人。适合构建、爬虫、夜里跑的任务；不适合有人在等的东
西。是这种的话，`dashboard cpu` 会在额度那一行写明。

== 内存：内核会杀掉最大的那个进程 ==

到内存上限时，内核先挤压你，然后杀掉这里面最大的进程。服务自己的日志里通常什么都
没有，因为服务不是自己失败的 —— 它是被打死的。一个不断消失又不报错的进程，几乎每
次都是这个原因。

    dmesg | tail        可能会写明被杀的是谁
    dashboard mem       你有多少，现在用了多少

交换空间不是额外的内存。它是给容器里那些一动不动的部分准备的地方，通常压缩着放在
内存里，所以冷页面的实际成本只是它标称的一小部分。用掉一点是健康的；用掉很多、而
且机器还很慢，说明工作集根本放不下，加交换空间也解决不了。

== 磁盘：写入直接失败 ==

到磁盘上限时，写入会以「no space left on device」失败，而当时正在写的那个东西怎么
处理，全看它自己 —— 数据库多半会停下来，包管理器多半留下装了一半的烂摊子。

`/` 和 `/data` 算在同一个数字里。最常见的两个元凶是没人轮转的日志和没人清的包缓存：

    du -xh --max-depth=1 / | sort -h | tail
    journalctl --vacuum-size=100M
    apt clean          # 或者：dnf clean all

== 流量：只有这一项会把容器停掉 ==

流量配额是这里唯一一个不是让你变慢、而是把容器从你手里拿走的限制。

进出双向都算，而且什么都算 —— 域名、公网端口、一次 apt update、你自己要求重装时拉
的镜像。它按周期统计，周期从主机方选定的某一天开始（登录屏和 `dashboard net` 都会
写明当前周期是哪天开始的）。

到 80% 时面板记一条警告。到 100% 时容器会被暂停，也就是停机 —— 不是删除，你磁盘上
的任何东西都不会被动。周期滚动到下一轮它会自己回来，主机方提高配额则更快。不需要
任何人去点什么。

== 到期 ==

每个容器都有到期日。日期一过，容器停机，SSH 登录被禁用。任何东西都不会被删除 ——
到期是一个开关，不是一把扫帚。找主机方续期，日期往后一挪它立刻回来，数据一样，登
录方式一样。

这个日期每次登录都会显示，`dashboard box` 里还会告诉你还剩几天。

== 什么是不受限的 ==

这里不限制你跑什么，也不检查你跑什么。真正存在的限制是：你的容器改不了机器的网络、
看不到任何其他容器、也没法把机器搞停。这些是墙，也正因为有这些墙，其余的事情才归
你自己说了算。
