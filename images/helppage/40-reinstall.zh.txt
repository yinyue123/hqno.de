title: 重装与 /data
summary: 重装保留什么、毁掉什么，以及动手之前该做什么

容器页面上有两个看起来差不多的按钮，实际完全不是一个量级的东西。

== 重启是安全的 ==

它把容器停掉再启动。文件系统、装的包、配置和数据都不动。服务卡死了用它，任何你平时
会重启一台机器来解决的情况也用它。

在这里面，`poweroff` 和 `halt` 同样有效，而且说到做到：容器会保持关机，不会被自动
拉起来。要再开机，去面板上点 —— 关机期间没有办法从 SSH 回来，因为 SSH 就是从容器
里进来的。

== 重装会毁掉除 /data 以外的一切 ==

它清空 `/` 并用一个全新镜像重建。你装的每一个包、配的每一个服务、放在 /data 之外的
每一个文件：没了，而且找不回来。所以那个对话框会要求你手打容器的名字。

重装后还在的：

    /data                     它存在的全部意义 —— 见下
    你的 SSH 登录名和密码
    你 SSH 连的地址和端口
    你的域名，以及主机方给你开的公网端口
    你的流量计数和到期日

重装后没有的：

    /  下面除 /data 以外的一切
    所有的包，包括 app-setup 装的那些
    你建的用户、crontab、systemd 单元、放在 /data 之外的证书，以及 /root 里的一切
    /etc/app-setup/secrets —— app-setup 给你生成的数据库密码。先拷出来，
      否则你会还原出一份自己打不开的备份

== /data，以及它诚实的边界 ==

/data 是单独挂在 /data 上的一块盘，也是重装唯一会留下的路径。数据库、上传文件、站
点内容、任何丢了会让你难受的东西：放那儿，并把服务指过去。

它不是这两样东西：

- 它不是备份。它能扛住重装，但扛不住 `rm -rf`、一次失败的迁移、一段勒索脚本，或者
  机器上一块坏掉的硬盘。备份是放在别处的一份副本 —— 而这件事正好有一张卡片：
  `app-setup install backup` 每晚把数据库和站点打包进 /data/backups，并上传到你
  指定的存储桶。
- 它不是白送的空间。它和 `/` 算在同一个磁盘数字里，`dashboard disk` 会把两者一起
  显示。

也不是每个容器都有。如果 `dashboard disk` 里没有 /data 那一行，说明这个容器卖出来
就没有 —— 找主机方，它在创建时就固定了，事后加不了，除非重建。

== 从菜单装的数据库已经在上面了 ==

这个容器有数据盘时，`app-setup` 会把数据库的文件放到数据盘上，而不是发行版
通常的那个路径 —— MariaDB 在 /data/mysql，PostgreSQL 在 /data/postgresql，
Redis 在 /data/redis，MongoDB 在 /data/mongodb —— 并且把 /var/lib/mysql 这些
老路径指过去，所以你已经知道的每条路径、每篇教程照样管用。网站根目录同理：
/var/www/html 是一个指向 /data/www 的链接，站点的上传文件在活得下来的那块盘上。

这样查：

    app-setup doctor | grep "data disk"

三种回答，只有第一种是好消息：

    yes — /data survives a reinstall, and is where databases go
    NO  — /data is a plain directory here; a reinstall takes it
    no  — this container has no /data; a reinstall takes everything

要多看一眼的是中间那种。一个叫 /data 但并不是磁盘的普通目录，从容器里面看跟真
的数据盘一模一样，然后跟着根文件系统一起消失。

如果你的数据库是在这个改动之前装的，它还在发行版原来那个位置。停机拷一次就能
搬过去：

    app-setup movedata mysql

== 重装之前 ==

1. 跑一次备份，或者手工把你要的东西拷到这个容器以外的地方：

       app-setup backup mysql          # 装了「备份」卡片的话
       app-setup dump mysql            # 或者导出一份 .sql 到 /data/dumps
       tar czf - /etc/nginx /etc/app-setup/secrets /root \
           | ssh 你@别处 'cat > box.tgz'

2. 记下你装过什么。`app-setup list` 会打印出来；重装完的机器不会记得。

3. 看看 /data 里实际有什么，而不是你以为放进去了什么：

       du -xh --max-depth=1 /data

4. 记下服务配置。/etc 里的配置文件不在 /data 里，而这正是大家会丢的东西。

== 选镜像 ==

对话框里列的是主机方在那台机器上缓存好的镜像。它们几秒就解包完，不消耗你的流量，
这是常规情况。

「我自己的镜像」—— 一个完整的仓库引用，比如 ghcr.io/you/thing:tag —— 是由机器去下
载的，所以它必须在机器那边能访问，而不是在你笔记本上能访问；由此有三个后果：

- 它只属于你，主机方不留副本；
- 正因为不留副本，每一次重装都会重新下载一遍；
- 这次下载每一次都算你的流量配额。

如果机器上恰好已经有完全相同的那个镜像，它会用自己的副本：不下载，也不计费。

== 在容器里直接重装 ==

在这个提示符下敲 `reinstall`，和面板上那个按钮做的是同一件事 —— 同一批镜像、
同一套规则、同样要确认。它的意义在于：你已经在 shell 里了，不必再去开浏览器。

    reinstall                  这个容器可以用哪些东西重建
    reinstall ubuntu-24.04     其中一个镜像。名字打一部分就行，只要只对上一个
    reinstall ref ghcr.io/you/thing:tag     你自己的镜像
    reinstall archive box.tar  主机方放在机器上的归档文件
    reinstall help             完整用法

单独一个 `reinstall` 永远不会真的重装 —— 它只列清单。指定镜像后，它会先把将要
发生的事说清楚，再要你把这个容器的名字打一遍，和对话框里一样；这一步直接回车就
是取消，什么都不会发生。

确认之后，你这条 SSH 会话就会断掉。这不是出错：重装做到一半时容器会被停掉，连接
自然跟着断。在容器里看不到进度条，因为那时已经没有「容器里」了。等一两分钟重新登
录就行 —— 地址不变，密码不变。

== 重装之后 ==

你的域名还指着这里，端口也还开着，但上面还没有东西在听 —— 原来应答的软件已经没了。
重新装上（`app-setup install ...`），指回 /data，然后确认：

    app-setup status nginx
    dashboard ports

之前设过开机自启的服务，那个设置跟着旧文件系统一起没了。再 `app-setup enable` 一次。
