title: 登录，以及别把自己关在外面
summary: 登录是怎么走的、密码怎么改，以及人们把自己锁在门外的四种方式

== 登录是怎么走的 ==

你不是 SSH 到这个容器，你是 SSH 到那台机器 —— 地址和端口就是 `dashboard ssh` 打印
的那一行，用户名是主机方给你的 —— 然后机器把你送进这里。所以端口常常不是 22，所以
让你确认的主机指纹是机器的指纹。

    dashboard ssh        要敲的那一行，原样在这儿

== 改密码 ==

在这里面跑 `passwd`。它改的是你登录用的那个密码 —— 容器自己的账号和机器校验的那个
登录，两边一起改，这是刻意保持同步的。

    passwd

别的办法都做不到这件事。手工编辑 /etc/shadow，或者用直接写它的工具，改的只是容器这
一份，机器校验的那一份不变，结果就是：这个密码在这里面 `su` 有效，登录却完全用不了。

在 ~/.ssh/authorized_keys 里放公钥对那个登录毫无作用。机器是在这个容器参与之前就把
你认证完了，它不会读这里面的文件。需要公钥登录就找主机方 —— 他们可以给你的登录名加
一把。（你自己装一个 sshd 并通过公网端口暴露出去，那是另一回事，它会正常读自己的
authorized_keys。）

主机方也可以在面板上给你设新密码。旧密码谁都看不到：它是哈希存的，这正是重点。

== 把自己锁在外面的四种方式 ==

1. `poweroff` —— 它有效，而且说到做到。容器会保持关机，而 SSH 恰恰是穿过容器进来
   的，所以没有任何办法再从 SSH 回去。去面板上把它开起来。

2. 在容器里开防火墙。任何过滤机器转发所用的那个回环地址的规则，同样会切断以同样方
   式转发进来的 SSH 会话。而且这里没什么可防的：除了主机方替你发布出去的东西，外面
   碰不到这个容器。

3. 把磁盘写满。到 100% 时，登录过程要写的东西写不进去，登录就会失败。在快满之前盯
   一眼 `dashboard disk`，该清什么见「配额」那一页。

4. 流量和到期。两者都会停机，而停掉的容器没有 SSH。流量会在周期滚动时自己恢复；到
   期得找主机方。这两个数字登录屏上都有 —— 它摆在那儿就是为了这个。

== 让东西一直跑着 ==

用镜像自带的 init 系统，别用你在 shell 里随手起的后台进程 —— SSH 会话一结束，没有
服务管理器托管的东西可能跟着一起没。

    app-setup enable nginx    开机自启
    systemctl status myapp    systemd 镜像上
    rc-service myapp status   Alpine（OpenRC）镜像上

`app-setup install` 会替它装的软件把这些配好。你自己的程序，给它写一个服务单元；
`screen` 或 `tmux` 的会话能扛住退出登录，但扛不住一次重启。

== 关于这台盒子，两件值得知道的事 ==

它是容器，不是虚拟机。内核是机器的，所以任何需要加载内核模块、需要自己的内核版本、
或者需要超出常规的 /dev 访问的东西，在这儿都跑不起来 —— 这一点在所有卖容器的服务商
那里都一样，不管面板管它叫什么。

你在这里面是 root，也仅仅在这里面。你做的任何事都到不了那台机器、机器上的其他容器、
或者它的网络。正是这些墙，让墙里面的一切归你。
