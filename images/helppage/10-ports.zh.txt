title: 端口与域名
summary: 两条入口，该用哪一条，各自由谁来开

外面的人要访问这个容器里跑的东西，只有两条路。花十秒钟选对，能省掉一下午。

== 域名，还是公网端口 ==

域名是一个名字 —— shop.example.com —— 它和这台机器上所有其他名字一起走 80 和
443 端口进来，机器按请求里的名字分发。它不占用机器任何资源，你自己就能加，凡是
说 HTTP 的东西都该用它：网站、API、后台面板、webhook。

公网端口是机器地址上的一个数字。别人输入 203.0.113.10:31000，连接就直接落到这里
面的 3000 端口 —— 没有名字，没有证书，中间也没有 web 服务器。凡是不是网站的东西
都该用它：游戏服、数据库、VPN、你自己的 SSH 服务、邮件服务。

    网站、API、任何 HTTP  ->  加域名
    其他所有              ->  要一个公网端口

== 域名：你自己就能加 ==

加名字不需要任何人批准。在这个容器里：

    domain add shop.example.com 3000
    domain ls
    domain del shop.example.com

那个数字是你的服务在「这里面」监听的端口。`domain add` 不带第三个参数，就是证书
交给机器管：它去申请、到期前自动续期，并把 http 和 https 都转发到你指定的端口。
绝大多数情况下这就是对的选择。

泛域名写法一样，覆盖它下面所有名字：

    domain add *.example.com 3000

如果你想自己终结 TLS —— 证书不方便交给机器，或者你跑的东西坚持自己握手 —— 就说
明一下，并给出你自己的 TLS 监听端口：

    domain add example.com 8443 self-hosted
    domain add example.com 8443 self-hosted 8080

第一条把加密流量原样透传到你的 8443，80 端口上什么都不放。第二条额外把明文 http
转发到你的 8080。

== 把名字解析到这台机器 ==

在这里加名字，只是告诉机器这个名字归你。它不会动 DNS —— DNS 在你买域名的地方。
去那边加一条 A 记录指向这台机器的地址（`dashboard ssh` 里就有），然后等几分钟。

在 DNS 指过来之前，托管证书是签不出来的：证明这个名字属于你的那次校验，恰恰要走
这个还没指过来的名字。新加的名字迟迟没有小锁，通常就是这个原因。

== 公网端口：由主机方来开 ==

你自己开不了，这是有意如此，不是漏做。域名不花成本 —— 一千个名字共用同样两个端口
—— 但公网端口是别人机器上的一个数字，两个租户都想要 31000 时，只有机器主人能裁决。

找主机方，告诉他们两件事：你的服务在这里面监听哪个端口，以及是 TCP 还是 UDP。外
面那个号码由他们挑。对他们来说就是点一个按钮。

他们给你开过的所有映射，在这里面都看得到：

    dashboard ports

== 端口开了却连不上 ==

这是最常见的故障，原因几乎总是同一个：你的服务监听在 127.0.0.1 上，而不是所有地
址上。从容器外面看，127.0.0.1 天然就不可达 —— 它的意思是「只限本机」，而转发这个
连接的机器并不是本机。

改成监听 0.0.0.0，并且确认一下你到底在听什么：

    ss -lntp

显示成 127.0.0.1:3000 的，从外面完全看不见；0.0.0.0:3000 才通。

域名也一样：机器的 web 服务器是通过分给你的回环地址把请求转发进来的，只绑
127.0.0.1 的服务在那边同样不会应答。

== 各自消耗什么 ==

两者都算进你的流量配额，进出双向都算，而且算法完全一样 —— 走域名的一个字节和走公
网端口的一个字节，是同一个字节。`dashboard net` 会告诉你这个周期用了多少、还剩多少。
